What This Accelerator Does

Archive old data and hold what must be kept

As business data grows, organizations need a structured approach to managing their data. This framework uses retention rules to decide which records stay in the active table, which are archived, and which are held. You can update the rules in config/retention_config.json without changing the main pipeline code.

This accelerator uses Databricks and Delta tables to:

  1. Read retention rules from the settings file.
  2. Set each record's status to active, hold or archived.
  3. Apply the configured rules for records that must be kept.
  4. Record run details and display the results.

Record decisions

Decision Meaning
ARCHIVE Mark an eligible old record as archived, so it appears in the archive table.
HOLD Keep a record that matches a configured hold rule.
KEEP Leave a record active because it is not yet eligible for archiving.

Record age is calculated using the date column specified in the settings, such as order_date.

Architecture

The retention pipeline applies the rules and updates the tables. The results notebook displays the output and runs checks.

Run 00_Setup first to prepare the data and tables. Then run the pipeline and results notebooks.

How it works

  • Calculate age. Find how old each record is on the run date.
  • Archive. Mark eligible records as archived.
  • Apply hold rules. Keep records that match the configured hold rules.

Notebooks

  1. 00_Setup: Checks the settings, creates the schema and tables, and loads the source data. Running it again leaves existing tables unchanged.
  2. 01_Retention_Pipeline: Applies the retention rules, processes eligible records, and logs each run. Use dry_run to preview actions only if all data-changing operations are correctly guarded in the code.
  3. 02_Results: Displays the output tables and run information.

Run order: 00_Setup, 01_Retention_Pipeline, then 02_Results. Run each notebook and wait for it to finish before starting the next one.

Output tables

<dataset> refers to the dataset name in the settings file.

Table What it holds
<dataset>_records All records with a status of active, hold or archived, plus archive date, run ID and rule.
<dataset>_active View of records that remain active, including records kept by hold rules.
<dataset>_archive View of archived records, including archive date and run ID.
ctl_retention_run_log Run details, including record counts, mode, and status.

Use It For Your Own Dataset

To use your own dataset, update config/retention_config.json and run the notebooks.

  1. Choose the date column used to calculate record age.
  2. Set the archive limit in days.
  3. Configure the rules that determine which records to keep, archive, or hold.

The setup notebook checks the configuration and reports errors, such as a hold rule that has day limits. Use yyyy-MM-dd for dates. Set a fixed as_of_date for repeatable results, or "today" to use the current date.

Prerequisites

  • A Databricks workspace.
  • Permission to create schemas and tables in the catalog.
  • Delta tables, which are supported by Databricks.
  • CSV files with column names matching the settings file.
